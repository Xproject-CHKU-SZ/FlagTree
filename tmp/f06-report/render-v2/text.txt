F06 融合测试结果与方法问题报告
阶段汇总截至 2026 年 11 月 5 日
F06 已在昆仑芯 P800 与 NVIDIA RTX 4090 两个平台开展验证，历史适配口径为 13 个融合模板变体，覆盖
FP32、FP16、BF16。本报告汇总已完成的公平计时实验、当前实现方法和主要问题，并附两平台逐例结果。这
里的“模板数量”不表示完整模型数量。

主要结果
P800 端到端优化后的自动路径完成 216 例测试，按当轮检查全部通过；其中 47 例使用资源融合或切分，169 例
复用原生执行路径。整体相对 eager 的 GPU / 端到端加速比分别为 1.131× / 1.129×。这些数字评价的是含原生
路径复用的自动选择系统，不能全部计为融合收益。[S1]

RTX 4090 完成 216 例两轮测试，F06 通过 213 例。通过样本相对 eager 的 GPU / 端到端加速比为 2.269× /
1.067×；相对有效 Inductor 对照为 0.956× / 1.962×。大矩阵 MatMul+Bias+Activation 的 36 例优化后全部通
过，GPU 与优化 Inductor 基本持平。[S2]

最新 P800 Mul+Sum 单乘并行修复完成 36 例：28 例通过普通有限值检查并计时，4 例通过本轮完整扩展验收。
并行化显著降低串行修复开销，但大矩阵 SDNN 分块仍远慢于 eager 与 Inductor，不能替换默认路径。[S4]

当前结论
主要瓶颈已从单纯的 Python 调用包装，进一步定位到 P800 的资源选择、过细分块、标量特殊值修复和同步。
复用 Inductor 并不保证资源、分块和生成代码与原生基线一致。当前尚未证明某一种 SDNN 或 cluster 方案在全
部尺寸上最优；大矩阵应允许多内核，并以完整调用实测决定是否采用。
各批次的检查集合、设备与源码快照不同，报告分别统计，不跨批次拼接倍率。正在准备的“整矩阵乘法 + 整行归约”新方案尚无
纳入本报告的正式 P800 全量结果。

当前方法与公平计时
复用 Inductor 的执行流程
静态 FX 图匹配与语义守卫 → 枚举资源和合法切分边界 → 调用 Inductor 编译、分解、调度与自动调优 → 检查
精度及真实生成内核 → 捕获前测量 GPU 和普通调用端到端 → 固定计划执行。小矩阵资源候选要求实际单内
核；大矩阵允许 SDNN 完整路径，或在 MatMul / Bias 后切分到 cluster。

自动选择先拒绝错误候选，再要求候选相对稳定基线在两轮普通调用中均至少降低 3% 端到端耗时，最后按 GPU
时间择优。没有合格资源候选时保留 eager 或 Inductor。原生路径复用是一项选择结果，不是融合已执行的证
明；设备执行错误必须单列，不能静默算作成功。

项目增加的是模板资格、资源计划、语义舍入/特殊值修复、推理入口和验收逻辑。Inductor 仍负责原生代码生
成与搜索；资源选择或 IR 修复会改变最终执行，因而“复用 Inductor”与“具有原生 Inductor 性能”不能等
同。

可以继续优化的部分

Mul+Sum 32×256 约差 9.02%，keepdim 约差 8.85%。这些是历史校准中的接近胜出项，可优先复测，但不能

使用 FP32 算术；30 个 MatMul 关闭提升后仍失败。依据用户选择，默认保持 BF16→FP32 兼容路径。

特殊值修复优化的效果与边界
NaN/Inf 修复针对运算语义，FP32 也需要检查。当前 P800 指令路径的特殊值处理可能与目标语义不同，因此不
能只凭“FP32”就移除修复。双乘与合并、整数分类修复及后续并行改写是本项目加入或改写的兼容逻辑，不应
描述为 FlagTree 官方固定实现。[S3、S4]

GELU tanh / SiLU 实验识别完整表达式，保留有限值算术和原始输入，调整受限激活输入及最终乘法操作数顺
序，以减少通用标量修复。SiLU 的 +Inf 路径已在目标用例中修复；它不代表所有 BF16 或组合已达到全范围语义
等价。

完整验收仍有缺口

已定位的调度问题
该 SDNN 对照由项目诊断脚本强制采用 256 列分块、XBLOCK=1 等保守配置，并关闭相应自动调优。2048 列因
此产生 8 个 SDNN 部分归约与 1 个 cluster 汇总，共 9 次启动。它不是原生 Inductor 的最优调优结果。cluster
完整融合 157.999 µs 与 Inductor 159.098 µs 接近，直接显示差距主要发生在特定 SDNN 调度路径。

原单乘整数分类进入逐元素标量循环。新方案把 128/256 列按完整缓存行分给 8 个控制核，每核处理 16/32 项，
仍需输入就绪与输出汇合两次同步。2048×2048 对应 16384 个行分块，累计 32768 个同步实例；这些实例分布
于设备执行，不能解释成全部串行的等待时间。

IR 还显示布局搬运与 SRAM 工作区。输入总读取逻辑量为两张 FP32 矩阵共 32 MiB；每个输入 16 MiB，不能误
写成 8 次重复全矩阵读取。32 KiB 工作区分配也不等于实际 DRAM 访问放大 32 倍。

GPU 时间占比的解释
3357.158 / 3400.626 = 98.72% 是 Graph 设备时间与普通调用 E2E 的比值，提示此方案主要受设备侧约束。设备
时间同时包含算术、访存、布局转换、同步和等待。PMU 查询未获得可用计数器，插桩也尚不能给出原 F06 的
互斥周期分解；真正算术执行占比目前未知。



当前方案的问题和后续工作
端到端开销已经定位并做了受保护的优化
逐层绕过实验显示，CompiledFxGraph 的 record_function 包装是此前退化的重要来源：单分区约 24–27 µs，
双分区提交阶段约 42–43 µs。固定 launcher 的收益较小，剩余开销还包含 AOT 包装、输出分配、设备/流处理
和实际执行。项目加入仅在合格推理条件下启用的轻量入口，profiler/debug 条件下恢复原生路径，并保留原生
收尾与分配。[S6]

BF16 计算格式与特殊值修复仍需逐层验证
BF16→FP32 可由 Inductor 的运算提升规则及厂商 FlagTree/XPU lowering 共同产生；项目另有舍入与特殊值
兼容处理。不能把最终所有 FP32 运算只归因于一个开关。关闭后端提升不等于形成原生 BF16 算术，实际 IR 必
须确认。显式 FP16 替代仅 18/72 例通过原检查，额外范围检查全部失败，当前继续保留 FP32 路径。[S7]

当前可实施的优化方向
大矩阵 Mul+Sum 应优先比较完整 cluster 融合，与完整乘法后接整行归约的双内核方案。切分时保留乘积
dtype 舍入和最终归约语义，恢复 Inductor 原生块尺寸与坐标下降调优；特殊值判定尽量进入 cluster 向量路
径，减少 SDNN 标量循环及跨核同步。

已实现显式启用的切分候选和 vector_multiply 实验入口，并完成 36 项本地单元检查。截至本报告封版，没有
经过本地校验的正式 P800 全量性能结果，故不列新方案加速比，也不改默认选择策略。后续实测仍限制同时只
使用一张正常 P800 卡。

验收顺序应为：普通有限值 → NaN/Inf 与极值/次正规数 → 实际二进制和资源绑定 → 同一 Graph 协议的 GPU
测量 → 普通调用端到端。任何一项失败均保留原因；即便局部修复较快，也不能写成全链路可用。

覆盖与证据缺口
需要补齐历史 Add+GELU exact/tanh、Add+SiLU 在大小矩阵与新公平口径下的测试；还需修复 RTX 4090 大矩
阵 BF16 bias-only 的 3 例失败。P800 完整模型吞吐、冷缓存、H2D/D2H 与并发负载不在本轮算子链路结果范围
内。
已完成专项的结果、二进制绑定与哈希已保存本地，专项共校验 648 个绑定文件，远端原测试目录已清理。新切分实验目录尚用于
待完成实验，不应在报告中宣称它也已经清理。
