    1.4 XPU 编程模型
             腾
         供
    XPU 编程模型是专门为昆仑芯 XPU 等异构计算设备设计的，旨在通过 CPU 与 XPU 的协同工
    作来突破传统 CPU 的计算瓶颈，开发和利用 XPU 的机器学习能力，有效解决能耗平衡和可扩

      仅
    展性等问题，同时 XPU C/C++兼顾终端和云目标平台。

    1.4.1 异构编程
    芯
    异构计算系统由 CPU（Host）和多个 XPU（Device）组成，Host 负责控制和调度，而
仑   Device 则专注于大规模并行计算和特定领域的计算任务。由于异构计算系统的特殊性，需要

昆   采用新的编程模型来适应这种架构。

    1.4.2 XPU 异构编程
    XPU 异构编程包括 Host 侧和 Device 侧的开发。Host 侧主要处理设备获取、数据准备、执
    行流程创建、任务描述、Kernel 启动和结果获取等任务。Device 侧则使用扩展的 XPU C/C+
    +语言编程，通过 Kernel 函数作为程序入口，并可以调用其他 Device 侧函数。
    混合编程流程

    让计算更智能 INTELLIGENT COMPUTING


    一种常见的混合编程流程是 Host 侧执行串行任务，并通过调用 XPU Kernel 函数让 Device
    侧并行执行计算任务。由于 CPU 和 XPU 的内存是相互独立的，因此在执行 Kernel 函数之
    前，需要将数据从 Host 侧内存拷贝到 Device 侧内存，并在计算完成后将数据从 Device 侧
    拷贝回 Host 侧。
    并行模式
    XPU 编程模型支持多种并行模式，包括使用 cluster_num 指定逻辑 Cluster 数量、core_num
    设置每个 Cluster 的逻辑核数以及 stream 创建多个任务队列来调度多个 Kernel。这些参数允
    许用户根据任务需求灵活配置并行策略，以提高计算效率。

                  腾

        仅
    原子访存接口的特性包括：

    芯   ● SM2REG 读取成功性：无论何时使用 SM2REG 指令读取共享内存，操作均能成功执
          行。
仑       ● REG2SM 写操作条件：使用 REG2SM 指令向共享内存的某一地址写入数据时，仅当该
          地址已被当前核心通过 SM2REG 指令读取，且之后没有其他核心通过 SM2REG 读取该
