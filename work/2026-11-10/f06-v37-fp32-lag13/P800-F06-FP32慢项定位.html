最终机器码中的差别

64×1024 的 MatMul + Bias + GELU（tanh）从厂商三核变为 mm_act 和 ew_gelu_tanh 两核。厂商 GELU 反汇编中可见 14 条 vmac.f.mz.rn；F06 的 GELU 核含 64 条 exp.f.rn。这些是静态程序指令。整条设备链的事件时间仍由约 15.5 降至 11.4 µs。

三个 Add + Softmax 的 _tle_row_softmax 分别含 128、256、512 条静态 exp.f.rn。尽管看到了这些标量指数指令，三个尺寸的完整设备时间均短于厂商独立加法和 softmax_fwd。厂商程序有少量无法解码的指令字，不能据此推断厂商未做指数运算。

512×1024 Add + SiLU 的融合核中可见 128 条 exp.f.rn 和 128 条 div.f.rn；2048×2048 选中 eager，实际发射 tensor_calc_k_nk 和 silu_fwd，和直接 eager 的两颗核逐字节一致。两个尺寸的慢因不同。

2048×2048 Add + SiLU 额外做了候选对照。直接 eager 和从 F06 调用 eager 设备回放分别为 73.52 与 73.94 µs，端到端分别为 92.39 与 102.37 µs。Inductor 与 cluster 的单核候选名称不同，但实际 设备程序完全相同，设备回放均为 82.72 µs，端到端分别为 143.55 和 110.43 µs。单核用向量乘加近似指数及倒数。SDNN 候选在混合特殊值输入的一个元素未通过校验。

Mul + Sum 的厂商程序将向量乘法的结果写出后再调用 reduce_mt；融合 _vector_rows 中同时可见 vmul.f.mz.rn 和 vadd.f.mz.rn。两个 512×1024 输出形状使用同一 SHA 和网格。MatMul + Bias + SiLU 的末核与厂商 silu_fwd 同 SHA，设备收益集中在合并矩阵乘和偏置的前段。
