P800 F06 · FP32 中间计算与最终舍入

在个人 Docker 的 P800 物理卡 6 上，对 13 个融合模板分别复测 FP16、BF16 和三个矩阵尺寸。输入和权重保留原始编码，FP32 参考由这些实际输入提升后执行同一模型，最终转回声明的 dtype。FP32 参考模型的参数预先提升，每次计时包含输入提升和最终转换；原始低精度 eager 逐算子舍入。两种基线分别实测。设备有其他工作负载，时间为本轮观测。

每个正式入口使用三个随机种子，验证 dtype、形状、新输出和留存结果。候选另验 NaN、正负无穷、改值和图重放，LayerNorm 增加高偏置输入。逐位差异计数来自首个随机输入；FP32 算术的归约顺序和超越函数实现也会影响最后一位。每个耗时由 96 个正反序配对同步样本取中位数，单位为 µs。

机器码与精度边界

BF16 MatMul + Bias，64×1024。抵消输入在原低精度 eager 中返回 0，默认 Inductor 和 FP32 参考分别返回 0.00195312 和 0.00195312。首组随机输入中，原 eager 和 FP32 参考有 18,391 个输出元素编码不同；正式入口有 0 个。实际发射及反汇编见上表。

早期 BF16 小矩阵加 ReLU 的故障发生于 Inductor 调优，异常前最后发射的 SDNN 程序 SHA256 以 b93a2949 开头，手写候选当时尚未运行。最终版本的普通 Inductor 使用 SDK FP32 矩阵乘，显式 F06 可选择已校验的混合输入 SDNN 核。宽化图的 Inductor 候选使用初始转换布局，避开了曾超时的坐标搜索。

默认 Inductor 的六个 Add + Softmax 组合均通过随机、Inf 及输出类型检查。64×1024 BF16 的 融合主体机器码 中有 6 个静态 exp.f.rn 指令位置。原 XPU 库对 FP32 libdevice.exp 发出了名为 Unsupported 的外部调用，链接失败；修订使用 Triton 的原生 exp 指令。

2048×2048 BF16 Mul + Sum 用 FP32 保存乘积，由 SDK 按其 FP32 归约顺序求和，再返回 BF16。正式路径为 eager。首组随机输入有 0 个元素与 FP32 参考的最终编码不同。此前另一个 FP32 求和顺序曾在 2,048 个输出中出现一个差 0.125 的元素。
