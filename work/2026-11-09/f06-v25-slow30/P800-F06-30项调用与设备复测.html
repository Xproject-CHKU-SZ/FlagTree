P800 个人 Docker · F06 30 项慢路径复测

显式 F06 自动选路，镜像 zhaoweiming/f06-p800:auto-inductor-final-20261109-v25。启用普通模块正式入口，FP32 / FP16 各 15 项。26 项走 eager，剩余路线为 cluster 2 项、sdnn 2 项。端到端快于直接 eager 的有 0/30 项。成功样本来自 P800 物理卡 [6]。

独立计时中，每条路线取 96 个交错样本的中位数。下表的 eager 是直接调用原模型；选用 eager 的 F06 仍经过正式模块入口。启动跟踪在独立标记段中执行，计时段不采集机器码。核数与后端分别由启动序列、二进制 SHA-256、资源类型和选中的同一计划对象交叉检查。

五类模板的瓶颈

Add + SiLU　两个 64×1024 均把两次厂商调用合并为一个 cluster 核，设备约 3.95–3.96 µs，对应 eager 为 8.97–9.17 µs。裸计划约 25 µs，正式入口约 39–40 µs。两档 512×1024 的 cluster 候选也有设备优势，但公开入口两轮未稳定快 3%。2048×2048 的厂商 SiLU 消费核约 52–56 µs，广播 Add 约 16–24 µs。

Add + LayerNorm、带仿射参数的 Add + LayerNorm　各六项全部退到厂商 Add 和 LayerNorm。Inductor 与 cluster 均在高偏置、低方差样本与 eager 的结果不一致。在正式选中的路线里，两套设备代码和发射配置相同，差距在主机提交。FP32 的独立 CPU FP64 对照可区分数值门槛和数学误差。

Mul + Sum、Mul + Sum（keepdim）　各有一个 FP32 64×1024 走 SDNN。它们把 Mul 和 Sum 合为一次启动，等批次数的设备计时约 8.45 µs，对应 eager 为 6.96–7.14 µs。裸计划快于直接 eager，但正式入口没有赢。FP16 小/中尺寸候选通过数值检查但设备计算较慢；大尺寸融合候选在含 Inf 的归约上与厂商结果不符。

精度对照

FP32 容差 rtol/atol 都是 0.0003，FP16 都是 0.003。下列独立诊断重用本镜像的候选生成器和相同算子参数。LayerNorm 输入先在 P800 完成加法和原始 dtype 舍入，再送 CPU FP64 归一化并舍入回原 dtype。

Add + SiLU · float32 · 512×1024 · sdnn　+Inf 输入时 eager=inf，候选=nan，FP64=inf；−Inf 输入时 eager=nan，候选=nan，FP64=nan。

Mul + Sum · float32 · 2048×2048 · cluster　同一行乘积含 inf，整矩阵的厂商 Sum 得到 nan，单取该行 Sum 得到 inf，CPU FP64 得到 inf，融合候选得到 inf。

Mul + Sum（keepdim） · float16 · 2048×2048 · cluster　同一行乘积含 inf，整矩阵的厂商 Sum 得到 nan，单取该行 Sum 得到 inf，CPU FP64 得到 inf，融合候选得到 inf。
