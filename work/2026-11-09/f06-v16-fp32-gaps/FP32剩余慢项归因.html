Mul+Sum 的三个尺寸

512×1024 的失败缩小到了独立的 P800 torch.sum。构造全 1 的矩阵，只令 [0,0] 为 NaN，沿最后一维求和后，未修改的第 21 行也得到 NaN。单独求第 21 行为 1024。keepdim 开关都复现。进一步将非有限值放在 [1,0]、[21,0]，多出的 NaN 分别出现在第 22、42 行。两张卡的最小实验一致。相同数据上融合候选在未修改行给出有限的 CPU 参考值。

64×1024 的两项已选 cluster，裸计划已经比直接 eager 慢，入口再增加耗时。2048×2048 的两项选回 eager。其 SDNN 候选的设备图计时约 31.5 µs，eager 约 35.5 µs。下表固定同一 _dsa_region_kernel 二进制、网格、实时执行流和新分配的输出，仅在隔离进程中用已绑定驱动入口替代每次 kernel[grid] 调用。

激活与临界项

三种尺寸的 Add + SiLU 中，SDNN 在加法结果为 +Inf 时返回 NaN，P800 eager 和 CPU FP64 均为 +Inf。小尺寸使用通过校验的 cluster，较快的裸计划被正式入口开销抵消。512×1024 的 cluster 设备执行略快，但裸计划已接近直接 eager。2048×2048 的 cluster 设备执行也慢于 eager，禁用尺寸回退后新出现的 flat_add 仍不能胜出。

64×1024 MatMul + Bias + GELU(tanh) 的 matmul K=64。偏置仅注入一个 +Inf 时，Inductor 对应的一列共 64 个元素输出 NaN，eager 与 CPU 参考均为 +Inf。默认小矩阵要求单核，已有 native_mm 使用两个内核。临时允许双核后，两张卡均通过原校验并选到 native_mm，正式入口仍比直接 eager 慢约 5 µs。

两个大尺寸临界项应分别处理。2048×2048 MatMul + Bias 在新冷编译的两张卡上都更快，设备 SDNN 计时约 24–25 µs，原矩阵约 30 µs。具体哪一个编译配置引起变化尚未单变量确认。2048×2048 Add + Softmax 的 cluster 裸计划快约 8–9 µs，正式入口抵消了这部分收益。这里比较普通同步调用，显式长期图回放不参与。

对应的修复方向

数值校验先补单独 NaN、+Inf 和 −Inf，分别覆盖张量输入与广播输入。LayerNorm 和 512×1024 的归约已取得纯 eager 复现，可据此核对厂商实现和项目要求的数值契约。

大尺寸归约可复用已编译 SDNN 启动器，同时保留对执行流、输出分配和输入签名的处理。小尺寸激活的验收基线应补上用户直接调用的 eager，用完整入口决定加速是否成立。
