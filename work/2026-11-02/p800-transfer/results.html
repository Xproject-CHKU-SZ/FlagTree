计时与验证

  • 未融合计算算子；原生 DMA 只搬运数据。SDNN 使用 SDK 编译结果中的 SRAM DMA 指令，cluster 使用 GM2LM / LM2GM，分别搜索块大小及可用流水配置。
  • 单向最终结果使用 R 次原生循环的 GPU 总时间除以 R。以单轮整个内核耗时 T(1) 为固定成本保守上界，所有点满足 T(1)/T(R) ≤ 0.5%；实际最大 0.400%。优选配置锁定后独立正反顺序采样，各点 22 个样本取中位数，并保留 P10/P90。
  • 拷贝与两阶段传递使用约 4 ms 累积的 Graph，正反顺序各 7 次，共 14 样本。普通调用加同步的端到端时间单独记录。小尺寸 Graph 次数翻倍校准：拷贝比值 0.9945–1.0067，主机传输 0.9913–1.0038。
  • 保持逐字节校验；输出预填 NaN，Graph 重放前修改源数据；原生 DMA 核对搬运字节计数和独立输入。没有放宽精度阈值。
  • 循环复用缓冲区；小工作集可能驻留 96 MiB L3。GB/s 是逻辑有效载荷带宽，不是硬件计数器测得的 HBM 总流量。这里是该 SDK 和搜索范围内的实测可达水平，并非硬件理论极限证明。
  • P800 OAM、Torch 2.9.0、FlagTree 0.7.1a1+xpu3.6；使用真实 XPU 驱动及 arch=3。torch.cuda 为兼容接口，计时启用 XPU_EVENT_KL3_ENABLE=1。

异常记录与文件保留

探索 cluster 原生 8 KiB 本地缓冲区配置时，物理 GPU 1、2 出现 NoC 超时；后续初始化进程也停滞，已仅终止本任务进程并避开这两张卡。没有执行设备复位。最终单向结果全部在正常的 GPU 0 完成。最终 xpu-smi 无本任务占用、ECC 计数为 0，这不等于证明 GPU 1、2 的计算功能已恢复，仍需管理员检查。

服务器没有下载依赖，没有修改系统配置。安装和测试文件仅位于 /data2/zhaoweiming/p800-transfer-20261102；2660 个归档文件已在本地逐一通过 SHA-256 校验。清理状态见下方回执。

远端测试目录已删除；释放约 26.80 GB。保留 /data2/zhaoweiming 父目录及其余文件。
