P800 F06 FP32 机器码与发射复核

个人 Docker v39c，P800-152 物理卡 6。正式曲线采用 v39c 的同步端到端样本和独立设备回放。本次重新核对每次实际发射的程序，分别记录模型入口、SDK 发射函数和后端可调用对象的时间。文中耗时单位均为 µs。矩阵乘的 K 为 64。

Softmax候选对照逐模板判断39 项机器码与计时

实测可优化的部分

  • 生成式 SDNN 的静态调用包装已在 7 个组合中完成同一机器码对照，三轮端到端节省的中位数范围为 5.77–7.59 µs。
  • 2048×2048 MatMul + Bias + GELU（tanh）只换矩阵阶段，仍发射两个核，设备时间从 113.58 降至 98.34 µs。
  • 2048×2048 仿射 LayerNorm 的现有行分块在所测候选中最快。小尺寸 Softmax 的 8 寄存器变体仅表现出较小的设备收益。

正式 39 项端到端和设备回放均快于 eager。eager 共发射 90 次，F06 共发射 45 次。eager 的 11 份与 F06 的 33 份不同设备程序合计 43 份，两个集合共享厂商 SiLU 尾核。按动态发射顺序、入口偏移、物理资源及 SHA-256 核验，39/39 项的分层计时复现了正式批次的两侧程序。三轮交错复测中，39 项在每一轮的同步端到端中位数均快于 eager。

在这 39 项中，F06 从模型入口到首次进入 xpu_launch_async 的中位数有 34 项比 eager 晚逾 3 µs。对应 SDK 函数自身耗时在 2.06–2.38 µs。完整模型入口比已选后端实现多出的提交耗时包含 Dynamo 守卫与模块调度。首核较晚与整体更快可同时出现，eager 还需要提交后续算子。

13 个模板的判断

  • Add + SiLU　中、大尺寸已用直接除法及片上偏置处理。大尺寸接近 eager，设备计算仍占主要时间。小尺寸与 Mul + Sum 共用密集指针启动器。
  • Add + Softmax　三个尺寸均为单个 cluster 核。主机首发开销可与其他模板对照，指数分组的额外调度实验见上表。
  • Add + LayerNorm　三个尺寸均保留厂商兼容的分段矩计算与归约顺序。核通过独立的有守卫启动器，评估参数缓存需覆盖实际 ABI。
  • Add + LayerNorm（仿射）　2048×2048 加仿射后，正式 F06 比无仿射多约 7.84 µs 设备时间，eager 两条对应路径相差约 1.68 µs。可检查权重、平移读入及时序；静态同步指令包含多条代码分支。
  • Add + GELU（exact）　小尺寸使用带 erf 的 cluster 核，中、大尺寸正式结果来自生成式 SDNN。512×1024 重新校准可选到 cluster 或其他 SDNN 程序，复用启动参数须按所选二进制验证。
  • Add + GELU（tanh）　三个尺寸均将广播与激活合为一核，设备回放尤其在大尺寸领先。小尺寸首发耗时可考虑共享入口优化。
  • MatMul + Bias　对齐 K=64 的大尺寸已使用分组矩阵乘并写回偏置。小尺寸的设备优势有限，但相对 eager 减少了一次发射。
  • MatMul + Bias + ReLU　三个尺寸均由原生生成式 SDNN 完成一个程序。首发时间和同一设备程序的入口对照支持优先减少热包装开销。
  • MatMul + Bias + SiLU　小、大尺寸保留厂商 SiLU 尾核，中尺寸为单核。单核 SDNN 激活存在已知精度约束，尾核的消除需要重新验证非有限值和输出舍入。
  • MatMul + Bias + GELU（exact）　中、大尺寸均为单个 SDNN 程序，可复用已校验的启动 ABI。小尺寸仍有两个程序，合并时须保留 exact GELU 结果。
  • MatMul + Bias + GELU（tanh）　三种尺寸均发射矩阵和逐元素两个程序。在大尺寸仅替换矩阵阶段并保持同一尾核即可做因果对照。
  • Mul + Sum　融合乘积和末维归约后仅一次发射，保留非有限值的补偿顺序。小、中尺寸的入口开销占比较大。
  • Mul + Sum（keepdim）　与对应 Mul + Sum 的实发程序、资源和拓扑逐项一致，差异主要体现在宿主的输出形状。两组可共享启动侧改进并分别验收输出形状。
