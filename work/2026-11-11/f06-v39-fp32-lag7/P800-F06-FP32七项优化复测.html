设备计算与选路依据

Add + SiLU 64x1024

64 行时原分块按包含 Python 提交的启动循环排名，短核容易被主机噪声盖住。改用图回放比较分块，缓存已验证的启动参数。通过验收的 flat 核在这个尺寸继续使用。

本轮实发程序　eager　2b77be6d + 9c1b998e　F06　e6da36b0

Add + SiLU 512x1024

原程序在指令流中有 128 条静态 exp.f.rn 和 128 条 div.f.rn，随后再乘输入。新实现将连续的 32 元素片段分成 768 份，每核处理 672 或 704 个元素，在每个 cluster 内共享偏置，向量相加后直接除以分母。FlagGems Kunlunxin 的直接除法及其分块、展开选项另外在同一张卡试跑，最快设备回放 17.38 µs；该数字仅代表移植到此融合表达式的选项组合。

本轮实发程序　eager　2b77be6d + 9c1b998e　F06　6534d5c1

Add + SiLU 2048x2048

v38f 回退后的两个程序与直接 eager 一致，正式入口又支付了一次守卫与提交成本。现在每个核用 512 个元素的两块局部缓冲，下一块读入与当前块的计算重叠。先向量相加，再按八个独立标量展开 exp 和除法。热调用读取本次输入与偏置，按最终保留的模型 dtype 写回。

本轮实发程序　eager　2b77be6d + 9c1b998e　F06　8d6d6160

Add + Softmax 512x1024

FlagGems 的末维 TLE 核同样在片上执行 max、exp、sum。v38f 已经单核，设备领先 eager。此处保留描述符形状、步幅和机器程序，缓存发射参数布局，地址、流和输出每次取新值。

本轮实发程序　eager　2b77be6d + c5f093d2　F06　0ab72553

Add + GELU (exact) 64x1024

FlagGems 和 F06 使用相同的 erf 形式。eager 在主机提交后续程序时，设备可以执行先前提交的工作；原 F06 的单核设备时间已短于 eager，原正式调用仍略慢。保留 exact GELU，按设备回放选块，减少热启动参数装配。

本轮实发程序　eager　2b77be6d + 345555e6　F06　be88a10f

MatMul + Bias 2048x2048

原 SDNN 单核已有设备优势；生成的 Inductor 包装仍检查参数对齐、设置设备并经过 CachingAutotuner。采用对齐完整块，K=64 作为常量，一维程序号按八行块分组复用权重。在校验过的 128×256 块中完成偏置写回，并绑定实际 SDNN 启动器。

本轮实发程序　eager　907ad80b + 2b77be6d　F06　30d5e126

MatMul + Bias + SiLU 2048x2048

原生 SDNN 的单核 SiLU 表达式在设备探针中误差约 0.00268，超出 FP32 容差 0.0003。保留正确的厂商 SiLU 尾核，复用分组矩阵乘与偏置核，缩短第一阶段。eager 先矩阵乘、再单独加偏置、最后做 SiLU。
