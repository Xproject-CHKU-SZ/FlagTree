# SDNN 适合哪些计算：单卡实测（2024-11-05 晚，P800 7 号卡）

运行环境：`flagtree-0.7.1a1+xpu3.6` + #1458 修复 core（`001cbc11…`）。
手写 Triton 微基准（`sdnn-fix/suit2.py`），f32 2048×2048，CUDA event 计时 100 次取均值。
绝对数是微基准量级（未做 Inductor 级调优），用于比较两类资源的相对行为。

| 计算 | 形态 | cluster | SDNN | SDNN 正确性 |
|---|---|---|---:|---|
| 逐元素乘（扁平 1D，XB=1024） | 同形状 | **219.9 µs** | 10153 µs | 正确 |
| silu（扁平 1D，XB=1024） | 一元 | **249.0 µs** | 9896 µs | 正确 |
| 逐元素乘（2D tile 64×256） | 同形状 | 2455 µs | **1369 µs** | 正确 |
| silu（2D tile 64×256） | 一元 | 2063 µs | **1367 µs** | 正确 |
| 广播乘（a×b，2D tile 64×256） | 广播 | 2311 µs | 1382 µs | **错误** max_abs 12.66 |
| 广播乘（XB=1） | 广播 | — | 10331 µs | 正确 |
| 行求和 N=256（XB=1 / RB=256） | 归约 | — | 1318 µs | 正确 |
| 行求和 N=2048（XB=1 / RB=128） | 归约 | — | 11336 µs | 正确 |
| 行求和 N=2048（XB=64） | 归约 | — | 11927 µs | **错误** max_abs 89.7 |
| 乘+行求和（Inductor 路径） | 融合 | **156.6 µs** | — | SDNN 融合在 XB>1 全错 |

## 结论

1. **SDNN 算得对的**：一元逐元素、同形状二元逐元素（2D tile，XB 任意）、以及 XBLOCK=1 的归约。
2. **SDNN 算错的**：广播二元逐元素且 XBLOCK>1；归约且 XBLOCK>1（含乘+求和融合）。
   这与前一轮定位一致：多行 tile 下 SDNN 的行维处理错误。
3. **性能上没有独占优势**：同一计算的最优形态相比，SDNN 比 cluster 慢 6–46×。
   2D tile 形态下 SDNN 反超 cluster（1369 vs 2455 µs），但 cluster 换扁平形态只需 220 µs，
   差距来自 cluster 的 2D tile 写法本身不佳，而不是 SDNN 更快。
4. 因此当前构建下，**没有一类计算适合交给 SDNN**：它能算对的都比 cluster 慢；它快的形态（多行）
   恰恰是错的。历史 1.90× 来自独立算子的另一种编译形态，不能外推到现在的管线。
