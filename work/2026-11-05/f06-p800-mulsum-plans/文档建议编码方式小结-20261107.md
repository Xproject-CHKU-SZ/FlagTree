# 厂商/官方文档建议的编码方式（KL3 / P800）

## A. 数据搬运（`how_to_write_copy/SKILL.md`）

1. **核心判据**：每个 GM 访问是否对应 DMA 原生形状；调 tile 参数救不了错误形状。
   反例：4096² f32 per-element gather **32.8 ms**，同字节 2D row transfer **114 µs**，aten 157 µs。
2. **原生形状**：`loop` 行连续段 + 独立的 src/dst 行 stride（`dma_cfg_2d`）；
   转置在**片上**做（`tl.trans` / `ds_shuffle_coa_1d`），GM 两侧保持行连续；
   外维折叠成 grid/标量偏移（不花传输成本）。
3. **四条路径**：平铺 TMA（cluster，launch 绑一次）→ 2D 行传输（`s_col==1`）→ 片上转置（`s_row==1`）→ 否则 fallback。
4. **三个静默错误必须拒绝**：strided 目的端、src stride=0 的广播、int→float cast（全 0）。
5. **尾巴用 `sizes=`，不要 mask**；buffer 保持静态满宽，只缩传输。
6. **tile 大小靠实测**：2048² f16 转置 64×64 = 66 µs，128×128 / 32×256 约 120–140 ms。
7. **`do_not_specialize`**：指针进入 specialization key 会导致"每次重载"（10–30 ms 级）。
8. **无法映射就 fallback**，并在同一改动里写"拒绝条件"。

## B. 归约（`how_to_write_reduce/references/reduce_envelope.md`）

1. **只支持最后一维归约**（`TLECoreTiling.cpp:383` 拒绝其他 axis）→ 中轴/0 轴只能"逐列累加器 + 循环折叠"，
   这正是归一化/Softmax 被迫两趟的原因。
2. **LM tile 上不要用 mask**：`tl.where` 在归约里 bf16 静默错、f16 编译失败；`tl.load(mask=)` 不合法；
   padding="zero" 不生效 → **用 zero-fill**（且仅当越界落在 tensor 外）；越界在 tensor 内则把最后一块回移。
3. **GM 指针侧可以 mask，但不要 clamp offset**（被丢弃 lane 会读元素 0 并贡献，实测差 24.3）。
4. **dtype**：f32/f16/bf16 精确；int 需 int64 累加器；bool 转 int8；设备无 f64。
5. **descriptor**：last stride 必须为 1；block 可大于 extent（会 clamp）；列切片必须传父行 stride。

## C. 归一化（`how_to_write_norm`）

1. **统计量写回就是性能本体**：30 µs 的融合 group_norm，(16,16,128) 上 tile+reduce+affine ≈6.9 µs，
   但 mean/rstd 两行 `[XBLOCK]` LM strip 的 store+copy 要 **+19.3 µs**。
2. **原因**：8 个 cluster 撞同一条 64B GM cache line（与 copy/reduce/fence/指令数无关）。
3. **解法**：走 **cluster-shared SM**（`scope=tle.gpu.smem`；SM 的 `local_ptr` 认索引；写回被合并成连续 `s_sm2gm`）
   → +19.3 µs 降到 **+0.8 µs**，speedup 0.6934 → 0.9687。
4. **bf16 走不了 SM 路径**（XPU3 无 addrspace 2 的 16-bit store；InstCombine 会折回）→ gate 回 LM。
5. **测量纪律**：`XPU_EVENT_KL3_ENABLE=1` 必须开；用 `CUDA_VISIBLE_DEVICES` 选卡；跑前探空闲卡；循环里留 aten canary。

## D. 数学/激活（XTDK 用户手册 V3.5 §3.1.2 + P800 架构说明）

厂商参考实现（C++）：

```cpp
const int buf_len = 1536;
__simd__ float local[buf_len];
partition(tid, nthreads, len, 16, &start, &end);     // 16 对齐一维分块
for (i = start; i < end; i += buf_len) {
    GM2LM(x + i, local, read_len * sizeof(T));
    do_cast<T,float>(local, local, read_len);        // primitive_cast（向量）
    primitive_exp<float>(local, local, read_len);    // 一次向量数学调用
    do_cast<float,T>(local, (T*)local, read_len);
    LM2GM(local, y + i, read_len * sizeof(T));
}
```

配套硬件约束：SIMD **512 bit = 16 fp32 / 32 fp16 每指令**；每 4 Group 共享 1 个 SFU（exp/log/sin）；
LM 32 KB/Group；GM→寄存器不可直达，必须先 LM/SM。

编译器侧（Triton）**等价编码**：
- EW 激活在 SDNN 上应走原生 LUT（`sdnn.ew … lut_func`），窗口固定 **[-8, 8]**（`min=-8, interval=0.015625, size=512`）；
- 窗口外需要精确 exp 时，厂商 C++ 有 `primitive_exp`（全范围），Triton 侧只有标量 `xpu::expf` → 超出窗口只能标量（慢）。

## E. 对照我们的实现

| 模板 | 文档建议 | 我们的实现 | 差距 |
|---|---|---|---|
| Copy/搬运类 | 2D 行传输、片上转置、sizes 尾巴 | 未用（本模板集无 copy 算子） | — |
| Mul+Sum | 最后一维、2D tile、zero-fill、无 mask | ✅ 2D tile + 分块折叠 | 已贴带宽地板 |
| Softmax | 最后一维归约 → 两趟 online | 三趟（max/sum/normalize） | 被 B2（CoreTiling 非法 IR）挡住 |
| LayerNorm | 统计量写回走 **SM**、bf16 gate 回 LM | 双 `[R,C]` f32 累加器常驻 VRF → spill | 未用 SM 方案——**工具链已支持**（`tle.gpu.smem`、`emitCoalescedSM2GM`），属本地待重写 |
| SiLU/GELU | 窗口内用 LUT、窗口外精确 exp | fp16 走 LUT（1.13–1.15×）、fp32 走 cluster 向量 exp（1.14–1.17×） | fp32 未用 LUT（窗口外精度不够） |
| MatMul+Bias/ReLU | 单内核 + epilogue | ✅ native_mm | 已贴算力峰值 |
| MatMul+GELU(exact) | LUT | ✅ `lut_func gelu` | 3.12× |

## 一句话

文档的"建议编码"可以概括为：**搬运匹配 DMA 形状、归约只走最后一维并用 zero-fill、归一化统计量走 SM、
数学走 LM 批处理 + 向量化（厂商 primitive_exp / 编译器原生 LUT）**；
我们已遵守的部分（Mul+Sum、MatMul）贴到地板，未遵守的部分（Softmax 三趟、LayerNorm VRF 累加器、激活窗口外标量 exp）正是剩余差距的来源。
