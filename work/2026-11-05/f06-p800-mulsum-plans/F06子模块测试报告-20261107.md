## 4. 子模块逐项

### 4.1 F06-G01 融合模板注册机制（P0）

- **判据**：新增模板无需修改统一调度主流程。
- **方法**：统计模板接入方式；新增一个真实模板（`native_mm`）检验接入成本。
- **证据**：
  - 12 个模板均以模块级 `match(gm, inputs)` + `compile(spec, tensors)` 提供能力，调度侧统一读取候选集合；
  - 新增 `native_mm`（`_p800_native_mm.py`）只需在 `candidate_plans` 追加候选、`compile_candidate` 增加分支，共 **2 处 hook**；
  - 覆盖矩阵中 11 例由 `NA` 直接执行。
- **结论**：部分达成。
- **缺口** `F06-G01-01`：注册仍需改调度文件 2 行 → 需改为注册表/装饰器驱动（判据：新增模板 0 行调度改动）。

### 4.2 F06-G02 合法性与数值约束（P0）

- **判据**：拒绝条件均有单测且不会误融合；覆盖 fp32/fp16/bf16。
- **方法**：匹配器级单测 19 项（`f06_legality_tests.py`），不依赖设备执行；数值用 atol=rtol=3e-3（f16）/3e-4（f32）。
- **证据（19/19 通过）**：

| 类别 | 用例 | 期望 | 结果 |
|---|---|---|---|
| 正例 | flat_silu、reduce_mulsum(2048²)、native_bias、native_relu、native 三形状 | 匹配 | ✅ |
| 布局 | flat/reduce/native 非连续输入（stride≠1） | 拒绝 | ✅ |
| dtype | flat a/b dtype 不一致、native bias dtype 不一致 | 拒绝 | ✅（**本轮修复**） |
| 形状 | b 长度 ≠ N、MatMul 输出形状不匹配 | 拒绝 | ✅ |
| 消费链 | GELU/SiLU 等未建模 epilogue 接在 `mm+add` 之后 | 拒绝 | ✅（**本轮修复**） |
| 别名 | `a+a` 输入 | 正确执行 | ✅ |
| 收益规则 | f16+2048²+bias 拒绝、f32 保留、f16 512 保留 | 按实测 | ✅ |

- **本轮修复的两个真实缺陷**：
  1. `_p800_flat` / `_p800_reduce` 未校验第二操作数 dtype → 已补 `b.dtype == a.dtype`；
  2. `native_mm` 未校验 `add` 之后的消费链 → 已加守卫：只接受 `mm→add→(relu)` 且直连 output；其它算子一律 decline。
- **数值**：f32 全部 `max_err = 0.0`；f16 全部 PASS（margin ≈ −0.002）。
- **结论**：达成（bf16 除外）。
- **缺口** `F06-G02-01`：bf16 未覆盖（模板 dtype 白名单仅 fp32/fp16，bf16 走回退）。

### 4.3 F06-G03 核心融合组合（P0）

- **判据**：MatMul+Bias、MatMul+Bias+Activation、Norm/Softmax/Reduce 组合在 XPU 正确融合并执行。
- **证据**：

| 组合 | 路由 | 结果 | 状态 |
|---|---|---|---|
| MatMul+Bias | native_mm | 1.05–1.44×（f32）、1.43–1.48×（f16 64/512） | ✅ |
| MatMul+Bias+ReLU | native_mm | 1.48–1.91×（全形状/双 dtype） | ✅ |
| MatMul+Bias+GELU(exact) | **sdnn（单内核）** | **1.22–3.12×**（修复 rank-1 pass 后新解锁） | ✅ |
| MatMul+Bias+GELU(tanh) | sdnn 编译通过但慢 4–25× → **decline** | 回退 eager/Inductor（1.00–1.82×） | ✅ 策略正确 |
| MatMul+Bias+SiLU | sdnn 编译通过但慢 1.4–25× → **decline** | 回退 eager/Inductor（1.00×） | ✅ 策略正确 |
| Mul+Sum（含 keepdim） | cluster | 1.10×（2048² f32） | ✅ |
| LayerNorm | cluster | 1.13–1.21×（64/512） | ✅（2048² 回退） |
| Softmax | 无（B2 深层） | 全部回退 1.00 | ❌ 官方（内核已重写：0.26–0.88×） |
| 点算子 SiLU/GELU | cluster / Inductor | 1.06–1.73× | ✅ |

- **结论**：部分达成。
- **缺口** `F06-G03-01`（官方）：Softmax 两趟 online 依赖 B2 深层，`TritonXPUCoreTiling` 输出非法 IR；
  `F06-G03-02`（官方）：GELU/SiLU epilogue 缺 `tt.sigmoid/tt.silu` lowering，且 SDNN 激活管线缺失导致 `error 702`。

### 4.3.1 本轮定位并修复的 MatMul 错误

- **现象**：MatMul+SiLU（512/2048）报 `error 702`（launch timeout）；MatMul+GELU(tanh/exact) 的融合路径编译失败，报
  `unsupported P800 SDNN rank-1 modulo load: expected a direct argument plus (pid * BLOCK + lane) % PERIOD with positive constant PERIOD and x < LENGTH mask`。
- **定位**：错误来自 #1458 修复引入的 `CaptureRank1Wrap` pass（`third_party/xpu/lib/Dialect/TritonXPU/Transforms/Rank1Wrap.cpp:103`）。
  该 pass 把所有"rank-1 + 含 modulo 的 load"都当作必须 wrap 的目标，**只要不完全匹配它的期望形式（要求 `arith.cmpi slt` 形式的 `x < LENGTH` mask）就 `signalPassFailure()`**。
  而 Inductor 为激活段生成的广播 load 形如 `x0 = xindex % 2048; tmp1 = tl.load(in_ptr0 + x0)`，**没有 mask**，
  因此每个经过 SDNN 激活段的 MatMul+Activation 区域都会在这里编译失败（记为 `error 702`/编译错误的表现不同）。
- **修复**：`Rank1Wrap.cpp` 改为**跳过不匹配的 load**（保留匹配模式的 wrap 修复；跳过时 `emitRemark` 计数），不再让整条 pipeline 失败。
  重新构建后 `libtriton.so` md5 `4d51b3f34f57`。
- **验证**（修复 + 策略，空闲卡，fp32）：

| 用例 | sdnn 修复后 | eager | 结果 |
|---|---:|---:|---|
| matmul_bias_gelu_exact 64×1024 | 31.1 | 37.8 | **1.22×** |
| matmul_bias_gelu_exact 512×1024 | 32.3 | 49.8 | **1.54×** |
| matmul_bias_gelu_exact 2048² | 90.5 | 282.0 | **3.12×** |
| matmul_bias_gelu_tanh（三形状） | 编译通过但 171.7 / 1132 / 8246 µs（0.03–0.24×） | — | 已 **decline**，回退 eager/Inductor |
| matmul_bias_silu（三形状） | 编译通过但 56.7 / 316.6 / 2289.9 µs（0.04–0.70×） | — | 已 **decline**，回退 eager/Inductor |

- **非矩阵模板回归验证**（同一修复库，空闲卡 4）：`add_gelu_exact 2048²` cluster 1.47×、`mul_sum 2048²` cluster 1.08×、
  `add_silu 64×1024` cluster 20.8 µs vs eager 20.2 µs（valid，差异在启动地板噪声内）→ cluster 路径未受影响。
  结论：**rank-1 pass 修复消除了 matmul+activation 的编译失败**；GELU(exact) 由此新获得 1.22–3.12×，
  GELU(tanh)/SiLU 的 SDNN 激活 lowering 仍然过慢（标量 tanh/sigmoid 路径），按实测 decline。

### 4.4 F06-G04 动态 Shape 融合（P0）

- **判据**：多 Shape 输入选择稳定且不产生错误缓存；验证对象动态 batch/seq。
- **证据**：
  - native_mm 在 64×1024 / 512×1024 / 2048×2048 均命中，结果 margin −0.0003；
  - 规则按 dtype/shape 生效：f16+2048²+bias decline、f32 保留、f16 512 保留（单测覆盖）；
  - 同进程内 3 形状顺序执行，无缓存串扰。
- **结论**：部分达成（静态多形状稳定）。
- **缺口** `F06-G04-01`：符号 Shape（dynamic batch/seq）未支持——matcher 读取具体 `int(a.shape)`，需引入符号维与资源约束（判据：动态输入选择稳定且不产生错误缓存）。

### 4.5 F06-G05 跨芯片收益治理（P1）

- **判据**：无普遍负收益融合，异常组合自动回退；两芯片起步后扩展。
- **证据**：
  - 回退门限（`FLAGTREE_FALLBACK_HEURISTIC`，默认开）：fp16 reduce n≥512、fp32 reduce m·n≤512K、softmax n≥512、layernorm m·n≥2048²、gelu m·n≤64K、fp32 silu m·n≥2048²；
  - 点算子 42/42 用例 ≥1.0（门限生效）；MatMul 仅 f16+2048²+bias decline（实测 0.85×）；
  - 回退目标为 eager（正确性等价），不是更慢的 Inductor。
- **结论**：部分达成（单芯片内负收益回退已生效）。
- **缺口** `F06-G05-01`：仅 P800 单芯片，无第二芯片 A/B、无白/黑名单版本化管理。
