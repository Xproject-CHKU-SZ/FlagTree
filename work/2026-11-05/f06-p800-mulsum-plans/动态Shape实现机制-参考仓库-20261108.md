# Xproject-CHKU-SZ/FlagTree 的动态 Shape 是怎么做的

仓库已克隆到 `work/xp-flagtree`（HEAD `84c3ce7`）。结论先行：
**该仓库没有自研的符号 Shape 编译器/传播框架**，动态 Shape 完全复用
PyTorch Inductor 的链路；FlagTree 只在 XPU codegen 层做了适配，另有两个通用
Triton IR 机制（`boundary_check`、tensor descriptor → pointer）和 `flagtree_hints`
通道。

## 1. 端到端链路

```
torch.compile(dynamic=True) / dynamo
   → FX 图（size 为 SymInt 符号值）
   → Inductor lowering（XPU 分支 _inductor_201/codegen/triton.py）
        · 动态时 numel 保持符号表达式，不烘焙常量
        · size_hints 用 hint 值（示例输入）只用于 tile/grid 启发式
        · 越界尾部通过 mask 谓词实现
   → Triton kernel（sizes 作为 i32 运行时参数，grid 运行时计算）
   → XPU backend（TritonXPU/LLVM，无动态 Shape 专用 pass）
```

## 2. 关键代码点

### 2.1 Inductor codegen（`third_party/xpu/backend/_inductor_201/codegen/triton.py`）

| 位置 | 作用 |
|---|---|
| L389 `if not dynamo_config.dynamic_shapes: self.codegen_static_numels(code)` | 动态 Shape 时**跳过**静态 numel 常量生成，numel 保持符号表达式（运行时 `xnumel` 参数） |
| L254–283 `V.graph.sizevars.size_hint(self.numels[i])` + `get_xpu_1d_hint/get_xpu_2d_hint` | 仍然**取 hint 值**（示例输入的尺寸）计算 XPU cluster/core 对齐的 tile 大小，只用于启发式/autotune，不是运行时 shape |
| L211–215 `self.indexing(index, dense_indexing=True)` + `mask_vars` / `mask` | 越界判定来自上游 Inductor 主体：`tl.store(ptr + offset, value, mask)`，动态 Shape 的尾部靠**逐元素谓词**兜底 |
| L376–382 `size_hints=... , tile_hint=...` | 生成 `@pointwise/@reduction/@persistent_reduction` 装饰器并带 size_hints |

### 2.2 Triton runtime

- sizes 是普通 `i32` kernel 参数，grid 在 launch 时按运行时值计算；
- 特化：`python/triton/runtime/jit.py:332-340,437-438` 的 `do_not_specialize` /
  `do_not_specialize_on_alignment`；默认会把 `==1` 与 `%16==0` 写进 cache key，
  因此**不同 shape 会重编译**（除非显式 `do_not_specialize`）。

### 2.3 Triton IR 层的两个"动态"机制

| 机制 | 位置 | 作用 |
|---|---|---|
| block pointer `boundary_check` | `lib/Dialect/Triton/Transforms/RewriteTensorPointer.cpp:150-160,323-334` | 将 `boundary_check` 维度转成 mask，块指针本身可带动态 shape/stride |
| tensor descriptor → pointer | `lib/Dialect/Triton/Transforms/RewriteTensorDescriptorToPointer.cpp:479-505` | 把 TMA 描述符拆成 **pointer + 每维 2 个 i64（dynamic shape/strides）+ padding 标志**（共 `1+2r+1` 个值），避免描述符要求静态 extent |
| `flagtree_hints` | `lib/Dialect/Triton/IR/Ops.cpp:68-78` | 通用 hints 字符串属性，是给后端的提示通道，**不是 shape 系统** |

### 2.4 XPU backend

- `third_party/xpu/backend/compiler.py` **没有任何动态 Shape pass**；
- 只有 `is_use_mask_zero`（L189）等 DMA/掩码选项，以及 SDNN/TLE 路径的静态 tile
  （描述符 block 必须静态，动态 Shape 下依赖上面的 descriptor→pointer 回退）；
- `TritonToTritonXPU`、`Vectorize` 里的 "dynamic" 字样都是无关语义（动态非法性判定、
  动态统计），不是 shape 支持。

## 3. 评估：能做什么、不能做什么

**能（Inductor 自带）**：
- `torch.compile(dynamic=True)` 的图可以走 TRITON 后端并运行；
- 动态维度作为运行时 `i32` 参数、尾部越界用 mask；
- 描述符路径在动态 extent 下回退到指针寻址。

**不能（仓库里没有）**：
1. 符号 Shape 在编译期的传播/约束求解（SymInt 只在 Inductor 图里，进不到 XPU compiler 的循环边界优化）；
2. Shape bucket / 动态 grid 规划；
3. 融合模板按符号 Shape 匹配（表内 F03 引用的 L389 只是**一个 flag 判断**，不等于实现）；
4. 动态 Shape 下的 tile 参数（size_hints 用 hint 值，换 shape 后已不是最优，最多保证正确）；
5. 免重编译（默认 shape 进 cache key）。

## 4. 对 F06-G04（动态 Shape 融合）的直接意义

可复用：
- `torch.compile(dynamic=True)` + Inductor 作为"动态 Shape 兜底通道"；
- `boundary_check` 与 descriptor→pointer 作为我们 kernel 的越界处理手段；
- `do_not_specialize` 把 m/n 移出特化键，减少重编译。

需要自建：
1. kernel 的 `N/R/C` 从 `constexpr` 改为运行时参数 + `do_not_specialize` + 掩码；
2. matcher 接受 SymInt（用 `size_hint` 做资源/预算判断，用 `>=` 分数做拒绝）；
3. 融合模板的资源预算按 hint 估算，超预算回退 eager/非融合；
4. cache key 去掉具体 shape（或做 shape bucket），否则动态 Shape 收益被重编译吃掉；
5. TLE/描述符路径在动态 extent 下自动走 descriptor→pointer 回退。

结论：参考仓库的动态 Shape = **Inductor 原生能力 + 两个 Triton IR 回退机制**；
F06-G04 若要在融合模板层面支持，需要我们自己补符号 Shape 匹配与运行时尺寸 kernel，
这也是表内 F03 缺口（符号 Shape 约束传播）的直接依赖。
