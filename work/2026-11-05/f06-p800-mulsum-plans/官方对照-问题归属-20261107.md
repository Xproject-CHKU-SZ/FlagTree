# 官方 FlagTree 纯净构建 vs 本地：问题归属对照

## 0. 官方构建方式

| 项 | 内容 |
|---|---|
| 仓库 | `https://github.com/flagos-ai/FlagTree`，HEAD `d65b6d7`（[CI] Fix the notification run name…） |
| 本地路径 | `work/official/FlagTree`（纯净 clone，仅加两处**构建**改动：删 `-Werror`；未改任何编译器源码） |
| 依赖 | 复用本地厂商 bundle（47 个 `.o`、5 个 `.a`、libdevice `.bc`）；LLVM 22.1.8 |
| 配置 | `-DFLAGTREE_BACKEND=xpu -DTRITON_CODEGEN_BACKENDS=xpu`（缺前者会缺 spec_cpp include 而编译失败） |
| 产物 | `work/official/build/libtriton.so`（225 MB） |
| 运行方式 | 在 P800 上用该 lib + **官方** `backend/compiler.py` + 纯净 triton 包（已删掉本地 `graph_fusion`） |

## 1. 四组对照测试（官方纯净构建，P800 空闲卡）

| # | 现象 | 官方 HEAD 结果 | 本地结果 | 归属 |
|---|---|---|---|---|
| T1 | `tl.math.exp2(x)` 是否等于 2^x | **err vs exp2 = 165.0，err vs exp(e^x) = 0.0** → 算的是 e^x | 已修复（`Exp2ToExpScaledPattern`）→ 0 | **官方 bug**（本地修复） |
| T2 | SDNN 上 SiLU EW（`z/(1+exp(-z))`） | **KeyError `'tt.silu'`**（LUT 表缺项） | 补表后 45.4 µs、err 1.55e-05 | **官方缺失能力**（本地扩展） |
| T3 | SDNN 上 modulo 广播 load（`b[i % 1024]`） | **编译通过但结果错：err 38.4**（无 rank-1 wrap 处理） | PR 分支加 pass（原为致命错误）→ 我们改为跳过 → 正确 | **官方静默错误 + PR 补丁过严**（本地修复） |
| T4 | matmul+silu 融合（dot+epilogue，SDNN） | **KeyError `'tt.silu'`**（同 T2） | fp16 1.13–1.15×、fp32 1.14–1.17× | 依赖本地扩展 |
| T5 | LUT 窗口 ±8 / fp32 精度 | 厂商对象（同一 bundle），同样受限 | 同样受限；用 cluster 路径规避 | **厂商预编译对象** |

## 2. 源码级差异（官方 vs 本地）

| 文件/目录 | 官方 HEAD | 本地 | 说明 |
|---|---|---|---|
| `lib/Dialect/TritonXPU/Transforms/Rank1Wrap.cpp` | **不存在** | 存在（cherry-pick PR `codex/p800-sdnn-modulo` #1458 + 本地放松） | T3 的根源 |
| `LegalizeExternEW.cpp` | 无 exp2 重写 | `Exp2ToExpScaledPattern` | T1 的修复 |
| `Vectorize.cpp` sigmoid 融合 | **已用 `isSplat` 正确版本** | 更早基线 + 本地修复 | 该 bug 官方已修，本地是旧基线 |
| `backend/compiler.py get_range_table` | 仅 `exp/exp2/log2/gelu` | 增加 `tt.tanh/tt.sigmoid/tt.silu` | T2/T4 的修复 |
| `python/triton/experimental/graph_fusion/` | **完全不存在** | 12 个融合模板 | 全部本地工作 |
| `backend/launch_config.py`、`resource_context.py`、`ReconcileLayoutUtils.h`、`Analysis/SDNN/*.a` | 不存在 | 存在 | 本地/厂商扩展 |
| vendor `.o/.a/.bc` | 仓库不含（setup 下载） | 已下载 | 两边使用同一份 bundle 做测试 |

## 3. 结论

1. **T1（exp2 错）是官方 bug**：官方 HEAD 上 `exp2` 直接返回 `e^x`，纯净构建可复现；
2. **T2/T4（`tt.silu` KeyError）是官方缺失能力**：官方 LUT 表只有 exp/exp2/log2/gelu，SiLU 的 LUT 路径在官方上直接报 KeyError；
3. **T3（modulo 静默错误）是官方行为**：官方没有 rank-1 wrap 处理，编译通过但结果错（err 38.4）；
   #1458 的 PR 用 fatal pass 修它，我们本地合并后遇到过严报错，已改为"不匹配则跳过 + emitRemark"；
4. **T5（LUT ±8 窗口）在厂商预编译对象里**，官方与本地一致，不是本地代码引入的；
5. **本地代码没有制造上述错误**：本地是在修官方 bug/缺失（exp2、rank1、LUT 表项），MatMul 融合模板本身是本地新增（官方没有 graph_fusion），其 fp32 精度问题来自厂商 LUT 窗口，已用 cluster 路径规避。
