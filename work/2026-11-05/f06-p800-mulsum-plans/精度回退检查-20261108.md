# 精度回退检查（本次改动后，2026-11-08）

判据与 harness 一致：`|out-ref| ≤ atol + rtol·|ref|`，fp32 atol/rtol 3e-4、fp16 3e-3。
参考为同 dtype 的 PyTorch eager 输出；fp16 额外与 fp32 真值比较。

| matmul+bias | fp32 | 3 尺寸 | k1 | 0.00e+00 | -3.0e-4 | PASS |
| matmul+bias | fp16 | 64/512 | k1 | 3.12e-02 | -2.1~-2.2e-3 | PASS |
| matmul+relu | fp32 | 3 尺寸 | k1 | 0.00e+00 | -3.0e-4 | PASS |

## 3. 结论：没有精度回退

1. **所有路径在 harness 门禁下 PASS**（含新增的融合 SiLU 与 split GELU）；
2. **唯一的变化**：fp32 matmul+SiLU 从 split 路径（误差 ~4.8e-07）改为融合 epilogue
   （误差 **1.97e-05**）。原因是融合路径在 dot 累加器上直接调用 `tl.sigmoid`
   （向量 vsigmoidf 近似），而 split EW 用的是 exp 形式。1.97e-05 仍比门禁小 **15×**，
   属可接受变化，不算回退到不合格；若某些场景需要 1e-7 级，可用
   `FLAGTREE_NATIVE_SILU_FUSED=0` 回退到精确 split（代价：64/512 形状约 1.6×，
   2048² 从 2.15× 降到 1.00×）；
3. **fp16 matmul 家族的 3.12e-02**（相对 eager）是 `tl.dot` 累加顺序造成的既有现象，
   与本次改动无关（matmul+bias/relu 未改动也有同样误差），且**我们相对 fp32 真值
   比 eager 更准**：ours-vs-fp32 1.45–1.56e-02 vs eager-vs-fp32 1.55–3.08e-02；
4. GELU split 的 4.77e-07 与 flat 逐元素完全一致，无新增误差。

## 4. 建议

- 保持融合 SiLU 默认开启（2.1×，精度余量 15×）；
- 若后续出现精度敏感场景，在 `native_mm.match` 里按 `M*N` 或 dtype 选择
  `silu_path='cluster'`（精确 exp）而不是全局关闭；
- fp16 GELU 若要启用 split，建议先在候选里加"输出 f32 再转换"的方案，避免
  累加顺序与 eager 的 3e-3 门禁冲突。
