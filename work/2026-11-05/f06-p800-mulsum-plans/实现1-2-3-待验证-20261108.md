## 1. TLE 软件流水（访存/数学重叠）—— `_p800_flat.py`

新增 `_tle_kernel()`：

- `tle.gpu.alloc([8, N], lmem)` 行块 + `tle.gpu.copy` 描述符 DMA（a 入、out 出，
  bias 一次拷入 bb）；
- 循环 `for r0 in tl.range(0, ROWS, 8, num_stages=2)`，配合编译器
  `add_tritonxpu_tle_pipeline_pass`（`compiler.py:435-447`）把 GM→LM fill
  旋转成 prefetch，实现 DMA 与数学重叠；
- 四种激活（silu / gelu_tanh / gelu_exact / relu）与 pointer kernel 完全一致；
- 接线：`run()` 内 `FLAGTREE_FLAT_TLE=1` 时优先走 TLE，**失败自动回退 pointer**；
  编译期还需 `TRITONXPU_TLE_PIPELINE=1`；
- 几何：`_TLE_R=8` 行/块、`_TLE_PROGRAMS=64` 程序，要求 `m % 64 == 0` 且
  `(m/64) % 8 == 0`、`n ∈ {512,1024,2048}`。

## 2. matmul + GELU(tanh/exact) split plan —— `_p800_native_mm.py`

- `match()` 新增 GELU 识别：`act_code = 3`（tanh）/ `4`（exact），要求
  `(M*N) % 8192 == 0`；
- 新增 EW kernel：
  - `ew_gelu_tanh`：`x*sigmoid(2*0.7978845608*(x+0.044715x³))`（向量 sigmoid）；
  - `ew_gelu_exact`：`0.5x(1+erf(x/√2))`（标量 erf）；
- `compile()`：先跑 matmul+bias（ACT=0），再对输出跑 1D 激活 kernel（in-place），
  `kernel_count=2`；
- 预期：matmul 36.3 + gelu_tanh ~82 ≈ **118 µs @2048²** vs eager 248.8 → **~2.1×**
  （原 Inductor 137.9 = 1.80×）；GELU(exact) split ≈ 203 µs vs eager 282（1.39×），
  仍慢于 SDNN LUT 的 90.5 µs（3.12×），由候选规划器择优。

验证：

```bash
F06_ROUTES=native_mm,cluster,eager python eager_table.py \
  matmul_bias_gelu_tanh,matmul_bias_gelu_exact 64x1024,512x1024,2048x2048 float32,float16
```

## 3. fp32 matmul+SiLU epilogue 融合（opt-in）—— `_p800_native_mm.py`

- `mm_act` 增加 `ACT == 3`：`z = z * tl.sigmoid(z)`（向量 sigmoid）；
- `match()` 在 `FLAGTREE_NATIVE_SILU_FUSED=1` 时把 fp32 SiLU 的路径设为
  `silu_path='epilogue'`，`compile()` 单 kernel 发射（`kernel_count=1`）；
- 若宽 fp32 tile 仍触发 `uni_sram`/dominate 编译失败，候选会抛错、规划器自动回退
  （split/Inductor/eager），因此启用本身是安全的；
- 预期收益：若编译通过，2048² fp32 matmul+silu 从回退 1.00 到 ~1.1–1.2×
  （single kernel 36.3+α vs eager 87.9）。

验证：

```bash
FLAGTREE_NATIVE_SILU_FUSED=1 F06_ROUTES=native_mm,cluster,eager python eager_table.py \
  matmul_bias_silu 512x1024,2048x2048 float32
```
