# F08 后续任务的 PPU 自动选卡规则（2026-10-22）

## 用户新授权

用户明确要求：“以后都是看到什么 PPU 没有被使用就用哪个”。
本规则替代旧方向文件中“仅物理 PPU 14、不自动换卡”的常规选卡限制。
后续已获准的设备任务可自动选择空闲卡，无需再逐卡询问；仍遵守已知的团队预约、
专用/保留/禁用卡及管理员限制，不把资源可见误当作突破这些限制的授权。

## 自动选择与启动

1. 使用现场 PPU 管理工具读取全部可见物理卡、完整进程表、利用率和显存。
   只读扫描，不初始化全部设备；记录时间戳和原始快照。
2. 候选卡必须同时满足：没有他人或未知进程、利用率为 0、显存处于已经认可的空载
   基线范围内、没有已知预约/保留限制。读取失败、进程表不完整、指标缺失时不猜测。
   不只看“显存很低”或“利用率 0”就放行；不自动连续上调空载基线阈值。
3. 记录候选列表、选中卡号与理由；多张符合条件时按确定性顺序选一张即可。
   使用团队预约/锁机制（若存在），在实际启动前再次检查，防止扫描后被他人占用。
4. 将选中的物理卡号作为一个显式参数传入驱动、worker、合法性分析和运行时绑定检查。
   在导入 torch/Triton 等设备运行时前设置 FLAGTREE_BACKEND=ppu 和相应设备可见性。
   不继承容器默认卡 0，不把逻辑 cuda:0 当成物理卡 0。
5. 启动后验证本任务 PID 确实位于选中的物理卡，并核对逻辑设备映射。
   后续占用核对要能识别本任务进程与他人进程；不能把自己的合法进程误当外部抢占，
   也不能为此忽略未知进程。映射不明、错误设备或未知占用则停止本任务，不杀他人任务。
6. 记录退出占用与本任务残留状态；只处理本任务明确归属的进程，不清理共享缓存。

## 实验一致性

- 不同的新任务组可以选择不同的空闲物理卡。
- 同一组 gate、正确性比较、交错 A/B 或长稳实验使用固定物理卡，记录型号及环境身份。
- 若执行前发现选中卡被占用，可重新扫描选择，但要重新绑定并重跑相应门禁。
  已经产生部分结果的任务组不得换卡继续拼表；保留原现场，另起完整任务组。
- 无符合条件的卡时等待或报告，不强占、不终止他人任务。

## 对旧代码的处理边界

已有 f08_flagtree_eval、f08_flagtree_checks、G03 合法性模块中仍有 card=14 的参数/校验。
这次更新的是任务指令与授权，不声称这些旧代码已经支持自动选卡。
真正使用其他卡前，要在新的非冻结版本中贯通：选卡参数、可见性、进程解析、worker CLI、
PID 映射、binding evidence、expected_physical_card 与新实验身份；先做 CPU 回归，再上卡。
不得全仓库把 14 文本替换掉，不改历史测量记录和历史证据中的物理卡号，
不修改旧冻结清单让新代码冒用旧身份，不关闭护栏来绕过旧版的卡号限制。

## 可直接发给服务器 AI 的补充指令

```text
更新后续常规选卡规则：用户已授权在团队允许使用的范围内，自动选择当时没有被使用的
PPU，不再固定 14，不需要每次询问具体卡号。已知预约/保留/禁用卡除外。

每个设备任务开始前读取全部卡的完整占用，候选须无他人/未知进程、利用率 0、显存在
认可空载基线内；启动前复查。把选中物理卡显式传给驱动和 worker，在设备初始化前设置
可见性，启动后验证 PID→物理卡→逻辑设备映射。不要继承默认卡 0。
同一组 gate/A-B/长稳固定一张卡；若被占用，保留现场，重新选卡并另起完整任务组，
不混卡拼表、不终止他人任务。无安全空闲卡则等待或停止，不自行放宽显存阈值。

旧代码写死 14 的地方不能只靠改 CUDA_VISIBLE_DEVICES 解决。先只读列出调用链，
在新的非冻结入口做卡号参数化和 CPU 反例回归，再用于新卡；历史卡 14 的证据保留。

当前已上传的 G02 admission 任务仍按原指令仅做 CPU 审计；这条选卡规则不自动授权
启动 G02 设备实现或性能实验。任务范围、FlagTree 核心方向、严格数值门禁、
原始证据保护和“只在用户要求时更新日报”的规则均不变。

阅读本规则后，若服务器活动方向文件还写“仅卡 14”，先备份并只更新其选卡条款，
保留其他服务器侧修改，记录 diff；不改任何冻结实验代码与清单。
```
