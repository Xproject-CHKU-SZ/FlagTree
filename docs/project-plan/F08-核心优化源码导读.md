# F08 核心优化源码导读

本导读对应 2026-10-24 的开发工作树。当前主线是模型级生命周期与合法同址复用，
由显式图级入口调用真实 FlagTree PPU kernel；不是全模型 FlagTree，也不是新 MLIR Pass。
本轮只增加中文 `#` 注释，不修改算法、算子、阈值、释放规则或计时协议。

## 建议阅读顺序

1. `python/scripts/f08_flagtree_top5_20261023_v3/execution.py::_execute`
   先看 `dest = args[index] if inplace else torch.empty_like(args[0])`。
   这是 Qwen 两臂的关键区别：让同一个已编译 Mul 写入独立输出，或写回合法输入。
   不先算一份结果再 copy，也不采用 ATen out= 代替 FlagTree。
2. `python/scripts/f08_flagtree_top5_20261023_v3/support.py::mul_candidate`
   看哪些节点可以进入优化集合，以及 `destination_arg` 从哪里来。
   只支持经过 G03 放行的直接 SiLU→等形状 Mul，不支持任意广播或 mask 乘法。
3. `python/flagtree/memory_planner/inplace_legality.py::evaluate_candidate`
   看为什么可以覆盖：全 storage 别名组、所有消费者、保护对象、偏移证据、
   副作用、顺序和 device/stream 一起检查。一个 tensor 最后使用不够。
4. `python/scripts/f08_flagtree_top5_20261023_v3/mul_kernel.py::compile_call`
   看目标地址如何进入实际编译 kernel，及 PPU backend/hgbin、四阶段产物和 launch 证据。
5. `python/flagtree/memory_planner/liveness.py::analyze_model_lifetimes`
   看每个 tensor 从哪里开始、到哪里结束，再把同一 storage 全部别名的寿命聚合。
6. `python/scripts/f08_flagtree_top5_20261023_v3/tuple_bindings.py::make_plan`
   看 max.dim 的两个 Tensor 叶子如何分别记账、与 getitem 合并别名并保留 tuple 所有权。

## BGE 的对应代码

- `python/scripts/f08_flagtree_eval/graph.py::execute_node`：`dest = x if inplace else torch.empty_like(x)`。
- `python/scripts/f08_flagtree_eval/kernel.py::_gelu`、`compile_call`：真实 FlagTree GELU 编译和外部目标绑定。
- `qwen.py::gate`：Qwen 专用取证/合法性/微探针/全图正确性接入，不是数学优化本身。

## G02 不要与当前 G03 结果混淆

`python/flagtree/memory_planner/offset_planner.py::_build_arena_plan` 使用 G1 生命周期，
以对齐的 first-fit 分配模型级 arena 偏移。`verify_safe` 检查任意安全布局，
`verify_matches` 另检查与确定性规划的一致性。

G02 是不同逻辑缓冲跨时段共用 arena 地址；G03 是当前算子合法覆盖自己的输入。
planner 的静态 assignment 不代表已经创建 arena、实际绑定或实现峰值收益。
既有 GELU-only arena 设备试验是机制成立但总峰值未下降的结果，不能借用 G03 收益。

## 当前已知诊断边界

v3 `execution.py::diagnose` 使用共享 GELU `execute_node`，并非 Qwen `_execute`；
`live_metadata` 只遍历直接 Tensor，跳过 tuple。Qwen 峰值诊断须另做适配，
不能简单去掉 worker 中的 BGE 限制。此处只加注释，不提前实现 v4。
